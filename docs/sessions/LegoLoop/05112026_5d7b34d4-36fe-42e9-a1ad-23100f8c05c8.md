## Clarificação: cada template, onde, o que faz, por quê

### Arquitetura geral

`docs/templates/` é a **Single Source of Truth (SSOT)** do LegoLoop. Os arquivos `.md` e `.json` são embutidos no binário Go via `go:embed` em `docs/templates/templates.go`. Os motores (`interview`, `specgen`, `plangen`) importam `legoloop/docs/templates` e usam os templates como molde estrutural. Os testes em `templates_test.go` garantem que nenhum motor diverge do template.

### Cascata de Governança (4 estágios sequenciais)

| # | Template | Formato | Motor Go que consome | O que faz | Por quê |
|---|----------|---------|----------------------|-----------|---------|
| **1** | `TEMPLATE_INTENT.md` | Markdown com placeholders `{{}}` | `internal/interview/intent_render.go` → `RenderIntent()` | Materializa o documento de intenção a partir do espelho socrático da entrevista. Mesmas seções, mesma ordem do template. O que a entrevista não respondeu vira "Não informado", nunca placeholder. | Responde **"por quê"**. Sem intent aprovada (confiança ≥ 95%), nenhum artefato downstream nasce. Gate: `!has_pattern('...', '\\{\\{')`. |
| **2** | `TEMPLATE_SPEC.md` | Markdown com placeholders `{{}}` | `internal/specgen/specgen.go` → `Generator.Generate()` | Gera a especificação técnica formal. O prompt ao LLM embute o template inteiro. Cabeçalho carimbado pelo motor (status, versão, link da intent, alvo). Placeholder não preenchido é rejeitado. | Responde **"o quê"**.
