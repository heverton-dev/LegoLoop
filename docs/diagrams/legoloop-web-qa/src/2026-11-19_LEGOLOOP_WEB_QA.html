LegoLoop · Processo Canônico

Arquitetura e Fluxo do Processo legoloop-web-qa

Processo canônico web-qa para auditoria determinística de web apps (playwright, obscura, aidd-linter-design, renderlint, axe-core, unlighthouse, lychee e lost-pixel), com relatório consolidado em docs/qa-web/ e encadeamento obrigatório para entrevista socrática até BUILD.

Processo: legoloop-web-qa Versão: 1.1.0 Nós: 12 nós sequenciais Gerado em: 2026-11-19T14:58:09

01 — Anatomia dos Nós do Processo

Estrutura isolada em contexto estéril com barreiras mecânicas de qualidade.

Preflight estrito das 8 ferramentas obrigatórias

Validação e verificação binária de todo o ferramental de QA

In: —
Out: preflight.json
Gate: exit_code == 0

Boot opcional de app local e descoberta de rotas e viewports

Consolidação de relatório JSON + Markdown em docs/qa-web/

Afunilamento investigativo das falhas encontradas

Out: INTERVIEW_CORRECAO.md
Gate: file_exists('scratch/webqa/INTERVIEW_CORRECAO.md') && word_count('scratch/webqa/INTERVIEW_CORRECAO.md') >= 50
n12_governanca_build · SKILL skill

Geração da cadeia INTERVIEW -> INTENT -> SPEC -> PLAN -> ROUTE -> DAG -> SWARM para BUILD

Materialização do ciclo formal para remediação e build

In: INTERVIEW_CORRECAO.md, RELATORIO_QA_WEB.json
Out: PACOTE_BUILD_SWARM.json
Gate: file_exists('docs/qa-web/PACOTE_BUILD_SWARM.json')

06 — Invariantes Operacionais & Regras Negativas

Políticas restritivas de segurança e critérios inegociáveis de execução do processo.

Zero Modificação do Alvo

A inspeção é estritamente analítica e hermética; o alvo original nunca é alterado em disco.

Evidências Fatuais Reais

Todas as métricas de AST e auditoria exigem arquivos físicos inspecionados sem mocks ou stubs.

Barreiras Binárias de Qualidade

Cada nó só avança após validação de exit code 0 e confirmação do gate mecânico de arquivo.
